把记忆从自托管 Lore 服务器迁移到 Loremem 云服务项目只需三步：从服务器获取备份文件，在 **安装** 页面导入，然后把 Agent 指向 Loremem 云服务。

> [!WARNING]
> 导入会替换当前项目的记忆。除非你确定要替换其中现有的内容，否则请导入到一个空项目中。

## 开始之前

- 选择要导入的 Loremem 云服务项目，并确认其中没有你需要保留的内容。
- 为你的自托管服务器重新做一份备份，并保存一份副本。在你的 Agent 能正常使用 Loremem 云服务之前，请保持自托管服务器运行。

## 1. 从自托管服务器导出备份

使用以下任一方法：

- 在自托管控制台中，打开 **设置 → 备份操作**，选择 **导出下载**。浏览器会保存一个 `lore-backup-<时间戳>.json` 文件。召回事件不会包含在内，这没有问题，因为云服务导入不会带入召回分析。
- 或者，从快照数据目录下的 `backups` 文件夹中复制一个文件。使用默认的 Docker Compose 部署时，路径为 `./data/snapshots/backups/`。使用 CLI 安装时，路径为 `~/.lore/docker/data/snapshots/backups/`。

确认该文件是 `lore-backup-v1` 导出文件。它的开头会标明格式：

```bash
head -c 120 lore-backup-2026-10-15-04-00-00.json
```

输出以 `{"format":"lore-backup-v1"` 开头。导入表单会拒绝其他格式的文件。

## 2. 在 Loremem 云服务中导入文件

1. 在 `https://app.loremem.com` 登录，并用项目切换器选择目标项目。
2. 打开 **安装** 页面。**开源版备份导入** 卡片位于令牌部分的下方。
3. 点击上传区域，或把 JSON 文件拖到该区域。卡片会显示文件名和大小。
4. 阅读 **高风险导入** 警告，然后勾选 **我确认这会替换当前项目记忆。**
5. 选择 **导入备份**。

导入完成后，卡片会报告导入了多少个节点、记忆记录和路径，并显示索引重建的结果，包括更新了多少个视图和术语 embedding。

## 导入了什么，跳过了什么

| 导入 | 跳过 |
| --- | --- |
| 记忆节点、路径和正文 | 设置，包括生命周期中的规则文本和策略 |
| 术语 | Dream 运行记录 |
| 记忆事件（历史） | 召回分析 |
| 每个节点的优先级和触发条件 | 生成的 embedding。视图和术语 embedding 会在导入过程中重建。 |

## 导入之后

1. 打开 **记忆** 页面，检查几条你熟悉的节点。如果你使用启动记忆（boot），也请检查它们。
2. 打开 **召回** 页面，运行两到三条真实的查询。
3. 打开 **设置**，检查导入时被跳过的内容，尤其是 **生命周期**（规则文本）、**策略**、**Dream** 和 **备份**。

如果导入提示记忆已导入但索引重建失败，那么记忆已经在项目中，但召回可能不完整。如果你熟悉的记忆仍然召回不到，请暂时不要依赖该项目，并保持自托管服务器运行，直到召回恢复正常。

## 重新接入 Agent

在你重新接入之前，Agent 仍会使用自托管服务器。自托管服务器的令牌无法在 Loremem 云服务上使用，因此请先创建一个 Loremem 云服务令牌。

1. 在 **安装** 页面填写 **令牌备注**，例如 `laptop`，然后选择 **创建令牌**。复制显示的安装命令。
2. 在每台机器上，用新令牌运行该命令：

   ```bash
   npx @loremem/cli install --base-url https://api.loremem.com --api-token lm_your_token
   ```

   CLI 会把新的服务器地址和令牌保存到 `~/.lore/config.json`。

3. 重启每个 Agent 运行时。钩子和 MCP 配置只在启动时加载。
4. 验证连接。运行 `npx @loremem/cli status`，然后在 Agent 中发送一条提示。在控制台的 **概览** 页面，最近查询表中应出现这条新查询。

> [!NOTE]
> 传入 `--api-token` 会把令牌写入你的 shell 历史记录。请像对待密钥一样处理这个令牌。
