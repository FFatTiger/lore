Rules copied across `CLAUDE.md`, `AGENTS.md`, and plugin prompts drift out of sync, and each copy goes stale on its own. What one agent learns stays locked in its own chat, so the next agent has to learn it again.

## What Lore does

Every connected agent runs the same loop:

1. **Boot.** At session start, Lore sends a fixed baseline: shared workflow rules, the persona, your stable preferences, and the rules for the current runtime.
2. **Recall.** Before each prompt, Lore adds a short `<recall>` block with the memories that might matter.
3. **Read before trust.** A recall line is a lead, not a fact. The agent opens the node with `lore_get_node` before it relies on the content.
4. **Write back.** When the agent learns a durable fact, it saves the fact as a memory node with the memory tools.
5. **Dream.** On a schedule (03:00 by default), Dream reviews the memory graph, fixes duplicates and vague triggers, and records every change.

Per-node history and backups make these changes reversible.

## Two ways to run Lore

Both options use the same agent plugins. The installer connects your agents to whichever server you choose.

| | Loremem Cloud | Self-hosted |
| --- | --- | --- |
| Who runs it | Loremem, at `https://app.loremem.com` | You, on your own machine or server |
| Setup | Sign in, create a token, and run the prefilled install command | Run `npx @loremem/cli`, choose Docker, then finish setup at `/setup` |
| Models | Preconfigured. Choose an embedding profile and a runtime LLM profile in Settings → Models. No API keys needed | Bring your own OpenAI-compatible embedding endpoint and a chat model for View LLM |
| Skills | Yes | No |
| Where data lives | Loremem's hosted service | Your machine or server |
| Cost | Free plan. Sign in with GitHub or Google | Free and open source (MIT). You pay for your host and any model APIs you use |

> [!NOTE]
> You can move a self-hosted memory to Loremem Cloud later by importing a backup. See [Import a self-hosted backup](/documents/cloud/import-self-hosted-backup).
